# Contributing

Development targets CPython 3.11–3.14, with Python 3.14 in `.python-version` for the
representative local environment, Node.js 22 in `.node-version`, pnpm 10.14.0 in
`package.json`, and JupyterLab 4.
Start from `develop`; ordinary changes return there through a pull request. Do not
push directly to `main` or `develop`.

```bash
uv sync --all-groups
pnpm install --frozen-lockfile
uv pip install -e '.[duckdb,viz]'
scripts/validate.sh
```

Frontend bundles are generated by `pnpm build:artifacts`. Commit the
JupyterLab bundle; the staged VSIX is ignored and embedded by the Python build. CI
rebuilds these assets and rejects source/bundle drift.

Upgrade pinned toolchains deliberately: update the conventional version file or
`packageManager` field, refresh `uv.lock` or `pnpm-lock.yaml`, rebuild generated
frontends, review dependency/license changes, and run the full validation entry point.

Tracked notebooks must have no outputs or execution counts and may retain only the
metadata accepted by `scripts/check_notebooks.py`, including intentional cell IDs and
tags. Never commit credentials, real account identifiers, internal hosts, warehouse
output, absolute machine paths, `.env`, or local frontend state.

Before requesting review, run `scripts/validate.sh`, explain tests performed, and add
a changelog entry for user-visible behavior or select the documented release-note
exemption in the pull-request template. The `ci:merge-ready` label authorizes and
requires the full compatibility, packaging, platform, and security suite.

Release branches are `release/vX.Y.Z` from `develop`; patch hotfixes are
`hotfix/vX.Y.Z` from `main`. Release maintainers own version synchronization,
generated assets, signed tags, TestPyPI rehearsal, production dispatch, release
evidence, and the `main` back-merge. See [RELEASING.md](RELEASING.md).
